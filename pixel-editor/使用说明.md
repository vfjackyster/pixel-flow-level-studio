# 像素关卡工坊

双击同目录下的 像素关卡编辑器.html，使用 Edge 或 Chrome 打开即可。无需安装、无需联网。
也可以打开 index.html，但应保留同目录的 data.js、core.js、app.js、style.css。

## 制作流程
1. 新建，输入宽高后点“应用”。左下角是坐标原点；缩小画布会提示裁剪。
2. 选择颜色，用画笔、矩形或填充绘图。橡皮移除像素；取色器拾取已有颜色。
3. 用框选工具划出区域，拖动选区移动；Delete删除，Esc取消。左右翻转只影响图案。
4. “按图案生成配平队列”按颜色拆分弹量并分散至各列，不保证可通关。
5. 拖动射手可跨列排序。点击射手，在属性区编辑颜色、弹药、所在列，再点“应用射手属性”。也有前移、后移、复制和删除按钮。
6. 设置等待槽、传送带容量、物理尺寸、难度标签，并点击“应用关卡设置”。
7. 检查供需差额，导出JSON保存作品。也可导出透明背景PNG。

## 保存与导入
草稿自动保存在当前浏览器。文件路径、浏览器或网页地址变化后，草稿可能不是同一份；请使用JSON备份。
导入支持本编辑器导出的JSON、已解码的普通像素原版关卡，以及浏览器支持时的gzip:压缩文本。
可选择文件或粘贴内容。浏览器若限制文件读取，使用粘贴内容导入。
新建、载入示例、清空、重生成队列均有确认；这些内容变更支持撤销。
快捷键：Ctrl+Z撤销，Ctrl+Shift+Z或Ctrl+Y重做，Ctrl+S导出。

## 第一版边界
只支持1×1普通像素与基础射手；有非空机关的原版关卡会拒绝导入，不会静默删除机关。
包含原版提取的34色材质色表，以及基础第1关的双色示例。
宽高4–160、2–5列、容量1–20，单体弹药1–9999，最多1000射手。
颜色配平不等于可解性验证。新增实时“调度模型失败率”和结构指标，具体公式与假设见 难度评估说明.md。已加入本地核心试玩，但尚无原版逐帧一致性验证、可解性穷举或经过玩家校准的真人难度预测。
导出沿用已确认的原版基础JSON字段结构，但contentHash清零、isValid=false；未验证可直接植入原游戏。
没有修改原APK，也不需要安装原游戏。

## 验证
数据测试：node test-core.cjs。
浏览器已验证：画笔、填充、矩形、撤销恢复、队列跨列拖动、属性应用、逐色差额、配平生成、JSON导出独立校验、粘贴导入、刷新恢复草稿。
文件选择器在自动化浏览器下遇到权限限制，未宣称文件选择导入链已通过；粘贴入口已通过。

实时评估在画笔松开、队列或属性应用后自动刷新。模型失败率不是官方难度或真人胜率；点击面板“计算逻辑、公式与适用范围”查看由来。

## 图片直接生成关卡
点击顶部“图片生成”。支持选择、拖入 PNG / JPG / WebP，或打开窗口后Ctrl+V粘贴图片。
1. 默认目标宽32格，可编辑宽高4–160；锁定原图比例时修改宽或高会联动另一边。
2. 完整保留会留透明边；填满画布会居中裁切；拉伸适配会改变图案比例。极端宽高比会受4–160范围限制，完整保留模式仍保持图像比例。
3. 每个目标格按覆盖面积与透明度计算平均RGB，再匹配34种材质中最近的颜色。用色上限2–34；超过上限时保留最常出现的材质，其余重新映射。算法不使用抖动。
4. 透明覆盖低于透明阈值的格子留空；透明像素的RGB不会污染平均色。白色背景仍然生成像素，不自动抠图。
5. 可在生成窗口设置射手单体弹量与队列列数；预览显示有效像素、用色与射手总数。
6. “生成并替换当前关卡”一次替换图案和队列，并自动配平各色总弹药。整次生成可以撤销。等待槽、传送带容量、物理尺寸与难度标签沿用当前设置。
7. 生成后继续绘图和调整队列，难度面板自动更新。超过1600像素或160射手时只显示结构指标，不显示旧难度分数。

图片仅本地处理，不上传；原图不写入关卡JSON或自动保存草稿。只保存生成的像素与射手数据。
最大文件12 MB、解码图像2400万像素，任一边不超过16000像素；预处理最长边降至2048像素。
图片生成不包含完整试玩或可解性保证。图片读取失败时，尝试重新保存为PNG或通过剪贴板粘贴。

图片转换验证：11项纯数据测试，覆盖精确材质匹配、坐标翻转、面积平均、透明阈值、RGB污染保护、留边、裁切、颜色上限、逐色配平和无效参数。
浏览器验证：剪贴板读取图片、比例联动、留边/裁切、用色限制、无效尺寸禁用、生成与整步撤销。
自动化浏览器的文件选择入口仍遇到图片解码/文件读取限制；没有将该入口宣称为已通过实机文件读取验证。
测试素材目录附有两张本地生成的PNG，供手动复核。

## 核心玩法试玩与JSON验证
点击顶部“试玩”，工具会先调用与导出相同的序列化函数，再从JSON文本重新解析关卡。运行时使用独立副本，不修改编辑原稿。
- 点击各列队首投放射手；等待区中有余弹的射手也能再次投放。
- 射手沿图案外围移动，只攻击当前所在侧、对齐行或列的第一个同色目标；被异色前沿挡住时不穿透、不扣弹。
- 子弹到达目标才消除像素，预占目标不重复发弹；弹尽射手离带释放容量。
- 一圈后仍有弹药的射手回到等待槽。等待槽填满本身不立即失败；带余弹射手到出口而无空槽时，按本地近似规则判失败。
- 支持暂停、继续、重开和0.5–4倍播放。圈时与射速可调整，重开生效。
- 试玩窗口内“导入JSON试玩”支持文件或粘贴导出的JSON。导入只替换试玩，不替换编辑稿。
- “JSON核对”显示画布、物理尺寸、像素数、射手数、与编辑稿的玩法数据比较，以及运行时目标/弹药/在途守恒。
- “导出验证记录”包含原始输入、规则版本与参数、时间点、操作轨迹、最近2000条事件及守恒结果。事件超出时记录丢弃条数，操作轨迹另行保留。

试玩还原范围：
已实现普通像素的四侧遮挡、颜色匹配、有限弹药、多射手传送带容量、队首顺序、等待槽与余弹回流。
方向、移速、射速、行列对齐、角落、投射物时间与失败时序属于本地约定，尚未与原版逐帧对齐；不包含机关、道具或动态减难。
本地默认顺时针从左下入口出发，一圈18秒、30发/秒、弹道0.14秒。满槽出口阻塞0.5秒且在途子弹已结算后失败。
运行使用固定1/120秒步进；窗口切到后台会暂停，避免恢复时跳过射击或出口结算。
清图通过只表示这一组本地规则下完成，不把导出JSON的isValid改成true，也不宣称已证明官方客户端兼容。
原有难度分数仍来自另一个简化调度模型，不能当作连续运动试玩的实测胜率。

试玩验证脚本：node test-play.cjs。16项测试覆盖导出重新读取、源数据隔离、遮挡、无目标不扣弹、容量/入口、在途结算、余弹回流、出口满槽失败、弹尽失败、暂停和确定性操作回放。

## 原版前10关
试玩窗口现已内置 Pixel Flow! 0.37.1 完整基础集合的第1至10关，也可导入“原版前10关”目录中的01.json至10.json。
原始图案、颜色、队列、弹药、隐藏标记和元数据均保留；来源与核查.json记录逐文件散列。
第8至10关含隐藏射手，后排显示问号，进入队首后揭示。这是本地机制还原，尚未与原客户端逐帧核对。
编辑器仍拒绝含隐藏机关的关卡编辑，避免编辑或重生成队列时丢失原始字段；这类关卡可以直接试玩。
本地速度、射击与失败时序仍为近似规则，测试通过不等于原版体验完全一致。
