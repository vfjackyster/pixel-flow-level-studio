# 核心玩法证据补充

本文件依据包内 IL2CPP 元数据和 ARM 机器码，未运行游戏。

## 已核查的射击链

- `ShootersOffenseController.TickShooter`，0x2693a34：检查网格尺寸、武器余弹、下一次可开火时间；根据射手位置取得所在侧；调用 `FindFrontTargetBest`。找不到目标（0x2693d3c–0x2693d40）跳到退出/更新时间路径，没有调用 `Shoot`。找到目标后预占伤害/目标，转向，0x2693f00 调用 `ShooterWeaponController.Shoot`。因此不能把“经过一圈”直接等同“扣固定弹药”。
- `FindFrontTargetBest`，0x2695190：按所在侧调用 `GatherAlignedRows` 或 `GatherAlignedCols`，使用 `FirstSolidsFromSideAxis` 取得前沿实心目标，并筛选障碍与合法目标。像素空间位置参与目标可达性，画面不是纯进度装饰。
- `IsValidTarget`，0x2697108：先检查目标状态/射手状态，然后 0x2697280 调用 `Shooter.get_Material`，读取该材质标识并通过目标接口匹配。完整特殊机关的匹配与阻挡规则未逐类穷尽。
- `ShooterWeaponController.Shoot` 的精确扣弹与特殊武器差异，本补充未独立逐条核查；不要把普通像素与所有机关统一简化成永久一弹一像素。

## 玩法抽象

玩家决策是把哪一列队首/哪个可用射手在何时送上传送带。射手有颜色和有限弹药，沿外围移动，在可攻击位置自动处理同色目标；未用完的射手需要等待区或再次投入。策略至少涉及：当前边缘暴露颜色、后续队列颜色顺序、射手余弹、带上占用与行进位置、等待区余量，以及机关状态。

主数据集中 `HasTimeLimit=false` 不表示“时间无关”：传送带移动与射速、目标被打掉的先后仍会改变某个射手本圈的产出。静态分析没有确定帧级输入接受顺序、所有回流分支及每个机关的完整时序。

## 避免错误建模

1. 不能只用每色总弹药与总像素数量评价可解性；颜色能否从某侧暴露、射手取用顺序和容量约束同样重要。
2. 不能把等待槽满这一状态直接等同瞬时失败；需核对传送带出口、余弹与投射物结算。
3. 不能将关卡 Difficulty 标签当作自动难度评分或真人胜率。
4. 不能将所有同号 funnel 变体都解释成连败替换；LevelEase 是另一条需单独跟踪的运行时处理链。
